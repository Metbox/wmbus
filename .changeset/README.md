# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a build tool that works with multi-package repos, or single-package repos to help you version and publish your code. You can find the full documentation for it [in our repository](https://github.com/changesets/changesets).

We have a quick list of common questions to get you started engaging with this project in [our documentation](https://github.com/changesets/changesets/blob/main/docs/common-questions.md).

## How it works for `@metbox/wmbus`

1. After making a change worth releasing, create a changeset:

   ```bash
   npm run changeset
   ```

   The CLI asks for the bump level (`patch` / `minor` / `major`) and a short
   summary. It writes a `.changeset/<adjective-noun-verb>.md` file you commit
   alongside your code change.

2. Open a PR. CI runs tests + build.

3. When the PR merges to `main`, the GitHub Actions release workflow opens
   (or updates) a "Version Packages" PR that consumes pending changesets,
   bumps `version` in `package.json`, and updates `CHANGELOG.md`.

4. Merging that "Version Packages" PR triggers npm publish to
   `@metbox/wmbus` with provenance. The released git tag matches the
   published version (e.g. `@metbox/wmbus@0.1.0`).

## Bump levels

- **patch** — bug fixes, internal refactors with no user-visible change
- **minor** — new drivers, new optional fields, new public API surface
- **major** — breaking change to the public exports in `src/index.ts`

When in doubt, use `patch`. It's safe to combine multiple changesets in one
release; the largest bump wins.
